# Self-Attention 与多头

## 从一句话核心到公式

[[Transformer|Transformer 的一句话核心]]：

> **每个输出帧 = 所有关键帧的加权平均，而"加权多少"是从数据本身算出来的。**

Q/K/V 就是"算这个权重"的标准做法。用图书馆比喻一下就懂：

| 符号 | 比方里是什么 | 作用 |
|---|---|---|
| **Q (Query)** | 这家图书馆的**提问**："我需要什么书？" | 用来和别人匹配 |
| **K (Key)** | 门口的**招牌**："我有什么书" | 用来被别人匹配 |
| **V (Value)** | 实际**藏书** | 真正被取走的内容 |

帧 i 想更新自己时：

1. 拿着提问（Q），挨家读别人的招牌（K）
2. 每读一家算匹配分：**提问和招牌有多契合** → `Q·K`（点积 = 相似度）
3. softmax 把分数变成"该听谁、各听几分之几"的权重
4. 按权重从各家藏书（V）抽内容掺在一起，作为新输出

写成矩阵：

```
分数    = Q · K^T           ← seq×seq 的相关性矩阵
权重    = softmax(分数)      ← 归一化，每行加起来=1
输出    = 权重 · V          ← 按权重取内容的加权平均
```

**所以 `Q·K^T·softmax·V` 不是魔法公式，就是"挨家匹配、按分取书"的矩阵写法。**

## 关键：权重是"活的"

- 死矩阵 `y = M·x`：`M` 固定，和 `x` 无关
- attention：`Q`、`K` 都从输入 `X` 算出（`Q=X·W_Q`, `K=X·W_K`），所以权重 `A=softmax(Q·K^T)` **随输入变**

"该听谁"是网络（经 `W_Q`、`W_K`）**根据当前输入当场算出来的**。这就是它能做全局规划的原因。

## 手算全程（3 帧 × 2 维）

### 设定：微型补间

3 帧，每帧 2 维"姿态特征"：

| 帧 | 角色 | 特征 |
|---|---|---|
| 帧0 | 上下文帧（已知） | `[1, 0]` 偏向 A |
| 帧1 | 缺失中间帧（要预测） | `[1, 1]` 占位 |
| 帧2 | 目标帧（已知） | `[0, 1]` 偏向 B |

输入 `X`：

```
1  0     ← 帧0
1  1     ← 帧1
0  1     ← 帧2
```

> 真实论文里这是 22 关节 × 6D 旋转 + 根位置 = 135 维；这里压到 2 维手算。

### Q/K/V 从哪来

真实 `Q=X·W_Q`, `K=X·W_K`, `V=X·W_V`（三个学出来的不同 W）。为手算干净，令 `W_Q=W_K=W_V=I`，于是 `Q=K=V=X`。

> 真实网络三 W 不同，让一帧的 query 匹配另一帧的 key；算术完全一样。

### Step 1：`Q·K^T` —— 算匹配分数

`S = X·X^T`，`S[i,j]` = 第 i 帧与第 j 帧的点积：

```
1  1  0
1  2  1
0  1  1
```

- `S[0,0]=1` 帧0 自身
- `S[0,1]=1` 帧0 与帧1 中等匹配
- `S[0,2]=0` 帧0 与帧2 正交（不匹配）
- `S[1,1]=2` 帧1 自身最高（`[1,1]` 模长最大）

> 真实还除以 `√d_k` 稳定梯度，这里省略，不影响结构。

### Step 2：softmax —— 归一化成权重

每行独立 softmax：

```
行0 [1,1,0]:  exp=[2.718, 2.718, 1.000]  和=6.436  →  [0.422, 0.422, 0.155]
行1 [1,2,1]:  exp=[2.718, 7.389, 2.718]  和=12.825 →  [0.212, 0.576, 0.212]
行2 [0,1,1]:  exp=[1.000, 2.718, 2.718]  和=6.436  →  [0.155, 0.422, 0.422]
```

读权重矩阵 `A`：

```
0.422  0.422  0.155     ← 帧0: 主要看自己和帧1，少看帧2
0.212  0.576  0.212     ← 帧1: 最看自己(0.576)，均匀看两端
0.155  0.422  0.422     ← 帧2: 主要看自己和帧1，少看帧0
```

### Step 3：`A·V` —— 加权混合

`V=X`：

```
帧0 = 0.422·[1,0] + 0.422·[1,1] + 0.155·[0,1] = [0.845, 0.578]
帧1 = 0.212·[1,0] + 0.576·[1,1] + 0.212·[0,1] = [0.788, 0.788]
帧2 = 0.155·[1,0] + 0.422·[1,1] + 0.422·[0,1] = [0.578, 0.845]
```

每帧输出都从原始姿态被拉向相关邻居——帧和帧发生了信息混合。

## 论文的关键操作：掩码

Context Transformer 里，过渡帧（帧1）是占位，**不应作为 key 被别人看**。用 attention mask 把过渡帧的**列**设成 `-inf`，softmax 后那列权重 → 0。

把帧1 作为 key 屏蔽（第 1 列 → `-inf`）：

```
S_masked:
1   -inf   0
1   -inf   1
0   -inf   1
```

重新 softmax：

```
行0 [1, -inf, 0]  → [0.731, 0, 0.269]
行1 [1, -inf, 1]  → [0.500, 0, 0.500]
行2 [0, -inf, 1]  → [0.269, 0, 0.731]
```

输出 `A·V`：

```
帧0 = 0.731·[1,0] + 0·[1,1] + 0.269·[0,1] = [0.731, 0.269]
帧1 = 0.500·[1,0] + 0·[1,1] + 0.500·[0,1] = [0.500, 0.500]   ← 正好两端中点!
帧2 = 0.269·[1,0] + 0·[1,1] + 0.731·[0,1] = [0.269, 0.731]
```

**这就是补间的本质**：被掩蔽的过渡帧只能从已知帧（上下文 + 目标）取信息，输出自然成了它们的（内容相关）混合。帧1 被迫只看帧0 和帧2，权重 0.5/0.5 → 输出 `[0.5, 0.5]` 落在两端中点。

> 论文里 W 是学出来的，所以不是死的中点、而是"懂运动"的非线性插值（知道过渡中段该加速、脚该离地等）。但**机制就是这个**——掩码 + attention 让占位帧从已知帧"抄"信息填自己。

## 多头

把 `d_model=512` 拆成 `H=8` 个头，每个 `d_head=64`。每个头独立做一套 Q/K/V 投影 + attention，最后拼回 512：

```
                 ┌─ head0 (64): Q0,K0,V0 → attention → out0
                 ├─ head1: ...
d_model=512 ────┤  ...
                 └─ head7: ...
                                          ↓ concat
                                    512 → W_O → 512
```

不同头能学不同关系（一个看时间近不近，一个看像不像目标帧）。论文 `n_head=8, d_head=64`。

### "一个头关注什么"是涌现的，不是写死的

**没有**在代码里写"这个头要关注近邻帧"。只是：
- 用位置编码（[[InbetweeningPositionalEncodings|PE]]）把位置信息注入进去
- 让每个头有**自己独立**的 `W_Q`、`W_K`、`W_V`（8 头 = 8 套不同投影矩阵）
- 用 SGD 在任务上训

训完**回头看**某个头的注意力权重图，发现"这个头恰好对近邻帧打分高"——这是**涌现结果**，不是设计。另一个头可能关注"离目标帧近不近"，第三个关注"姿态像不像"——因为它们 W 不同，学到了不同相关性标准。

> PE 提供位置信号，`W_Q`/`W_K` 学会利用它，"关注近邻"是训练后涌现的行为，不是单独某个矩阵负责的。

## W_Q 维度辨析

### 维度的两种等价看法

**看法 A（概念上，每个头单独）**：每个头 `h` 有自己的 `W_Q^(h) ∈ R^(512×64)`，8 个头 → 8 个矩阵。

**看法 B（代码实现，合并成一个大矩阵）**：代码 `nn.Linear(512, n_head·d_head = 8×64 = 512)`，即 `W_Q ∈ R^(512×512)`，一次算出 8 个头的 query 再 reshape 拆开：

```
Ĥ·W_Q ∈ R^(30×512)  → reshape (30, 8, 64) → transpose (8, 30, 64)
```

**两看法等价**：大矩阵 `W_Q(512×512)` 沿输出维切 8 块，每块 `(512×64)` 即 `W_Q^(h)`。

### `W_Q^(h)` 含义

`(h)` 是头的编号，`h∈{1..8}`。`W_Q^(h)` = "第 h 个头的 query 投影矩阵"。8 个头各有独立的 `W_Q^(h)`、`W_K^(h)`、`W_V^(h)`，**这就是多头的全部意义**——8 套不同投影，让每个头用不同标准算相关性。若 8 头 W 都一样，多头退化成单头。

> `W_O` 不带 `(h)`：它是**一个** `512×512` 矩阵，作用在"8 头拼好的 512 维"上，负责混合 8 个头的输出。

### `W_Q` 是和 H 做计算，还是 H 的函数？

**和 H 做矩阵乘法；W_Q 本身不是 H 的函数，是固定参数。**

| | 是什么 | 随输入变吗 |
|---|---|---|
| `W_Q` | 学出来的**参数矩阵**，训练完固定 | **不变** |
| `Ĥ=LayerNorm(H)` | 当前输入数据 | **变** |
| `Q = Ĥ·W_Q` | 运行时**算出来**的 query | **变**（因 Ĥ 变） |

公式 `Q = Ĥ·W_Q`：`W_Q` 是乘数（固定），不是 `H` 的函数。真正是 `H` 函数的是 `Q`，以及再往后的 `A=softmax(Q·K^T)`。

**attention 的 input 相关性全来自 `H` 流入 `Q`/`K`**，参数本身纹丝不动：

```
H 变 → Q=H·W_Q 变, K=H·W_K 变 → Q·K^T 变 → A 变
```

整条链只有 `H` 是数据（变），其余 `W` 都是固定参数。
