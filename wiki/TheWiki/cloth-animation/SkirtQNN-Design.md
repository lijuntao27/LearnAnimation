# SkirtQNN — 移动端时装裙摆骨骼准静态神经网络方案

> 项目设计笔记，非论文精炼页，持续更新。记录当前架构判断与"动态 clip → 静态 Pose 标签"的方法路径，后续会在本页继续展开。

## 项目背景与约束

- **规模**：已有 300+ 套时装，且没有对裙摆骨骼数量/结构做过统一限定——[[HyperBones2026]]、[[PhySkin2026]] 那种"固定几件服装联合训练一个模型"的路线在这里走不通；每新出一套时装大概率需要针对性输出骨架，也就需要针对性输出动画资源，裙摆穿模等问题随之而来。
- **绑定流程已定**：美术输出模型时已经定好基于骨骼的 LBS 绑定（裙摆骨骼结构由美术定，不是反解出来的）。因此"基于角色 Pose 实时推断裙摆骨骼 Pose"——即 [[Pan2022-VirtualBones]] 的骨骼驱动范式——是契合本项目的方向。
- **美术要求**（硬约束，需要在方案每一步都对齐）：
  - 有一定物理感，但不需要太拟真、太活跃；
  - 不能膨胀破坏版型；
  - 不能穿模，包括**自穿**；
  - 尽量紧贴身体，不要太松垮以避免露底。
- **数据预算**：每套新时装出 40000 帧级训练数据（[[Pan2022-VirtualBones|Pan 2022]] 的量级）不现实；**4000 帧是可接受范围**。

## 为什么排除 GRU 路线

[[Pan2022-VirtualBones|Pan 2022]] 的低频模块是 GRU 学"身体动作→骨骼 motion"的时序回归，需要 40000 帧×10 参数组；[[Jin2024-RopeChainQNN|Jin 2024]] §9 实证复现后指出其 "dynamics completely wrong"、holdout 泛化差——GRU 学的是**状态间时序转移**，覆盖各种动态情形需要的数据量本质上就大。本项目 4000 帧/套的预算下，GRU 路线的数据饥渴问题会被放大到不可接受，故排除。

对应地，[[QNN]]（[[Jin2024-RopeChainQNN|Jin 2024]] 提出）的思路是学**状态本身**而非状态转移：逐帧独立、不含时序，数据需求显著更小（Jin 2024 用 5000 帧）。这正是"思路1"要走的方向。

## 架构决策：QNN 定形 + 下游弹簧物理接力二级动态

**思路1**：运行时把美术要的"物理感"完全交给下游一套轻量弹簧骨骼二级运动方案（文中简称 Kawaii，类似 KawaiiPhysics 一类锚点驱动的阻尼弹簧解算器）负责；本项目的 QNN 只做 [[Pan2022-VirtualBones|Pan 2022]] 里"低频"那一层，且**不考虑时序，只出准静态 Pose**。

**与 [[PhySkin2026]] 的架构对照**：这与 PhySkin 的取舍高度同构——两者都是"主动放弃动态、只学准静态骨骼/节点变换"。但关键差异是 **PhySkin 没有下游物理层**，它自己的物理自监督 loss（拉伸+弯曲+碰撞+重力）必须同时扛住"物理合理"和"贴身不穿模"两件事；本项目有 Kawaii 接力二级运动，QNN 的输出可以**更保守、更偏紧贴/克制**，物理感的活力交给 Kawaii 兜底——这让"不能太活跃、紧贴身体"这条美术要求在网络侧更容易达标。

**为什么不走 [[HyperBones2026]] 的教师蒸馏路线**：HyperBones 用训练期物理积分教师（MeshGraphNet）蒸馏出动态，换来"零仿真数据但仍保留动态"，代价是训练成本高（warm-up 500 + 联合 99.5k epoch）且只支持固定几件服装联合训练。本项目每套时装独立出骨架、要求单套时装训练成本可控，且已有 Kawaii 在运行时零训练成本地补充动态——没有必要为"要不要动态"这件事再上一层教师网络。

**下游耦合的风险**（需要在训练阶段专门处理，见文末）：Kawaii 的弹簧是相对锚点做二级运动的，锚点就是 QNN 每帧输出的骨骼位置。若 QNN 输出帧间跳变，等于给 Kawaii 喂错误速度信号，会产生抽动、过冲。

### 现行范围与运行时动机（2026-09 更新，持续迭代中）

> 本会话澄清后的现状，压过上文"思路1"中过时的表述。核心分工：**权威动画怎么产出是美术侧的事，本方案只负责"给定一份权威动画数据，如何让它在运行时跑起来、并兼容所有混搭情况"。**

**权威动画（训练数据来源）——美术侧工作，不在本方案范围**：时装裙摆针对本套装动作播放的裙摆动画，由美术严格控制。当前项目已有动画资源均为**纯手K**；后续产出方式未定（可能是 Houdini 模拟+美术精修，也可能是 Pyrrha 在 UE 里物理模拟+美术精修）。无论哪种方式，本方案拿到手的输入是**美术已经调好风格的权威裙摆动画 clip**（带真实时序动态），工作从"如何把它转成静态标签 + 如何运行时跑起来"开始。

**运行时目标——全走 QNN，不播权威动画**：运行时不用再播权威动画本身，只发 QNN 权重（+ Pyrrha/Kawaii 物理资产配置），用 QNN 逐帧出锚点替代采样动画曲线。收益是**省掉裙摆动画资产的打包/加载，变相省包体**；前提是**效果美术能接受**。这是明确目标而非备选（若最终不可接受，见下方"Blend 兜底"灰度路径）。

**QNN 的两条验收线（分开负责，不混在一个指标里）**：
- **(a) QNN 逼近静态标签**：θ 在训练分布内时，$f(\theta)$ 与提取出的静态标签 $\Delta\chi_{static}(\theta)$ 的误差要小（骨骼位置/旋转误差分位数可量化）。这是纯监督回归问题，可直接量化打分。**"QNN 在训练姿势附近的输出逼近训练结果"是明确的验收目标之一**。
- **(b) 运行时整条链路逼近权威动画的视觉效果**：用同一条身体动作序列跑"QNN 锚点 → Pyrrha/Kawaii"整条运行时管线，出来的裙摆动画要跟美术权威动画（带摆动、惯性、时序动态）看起来像。这**不是 QNN 回归精度问题**——QNN 按设计是准静态、不产出时序动态，那部分手感全靠下游物理层复现。

**为什么 (b) 大概率可控——复用编辑器已调好的参数**：把数据产出方式从"Houdini 出动画"改为"Pyrrha/Kawaii 直接在 UE 编辑器出动画给美术精修"的核心原因正在于此——**美术在编辑器里调 Pyrrha/Kawaii 参数时，是看着最终效果调的；运行时复用同一套参数即可，理论上不需要再对物理层做任何离线标定**（这天然保证了下游物理层的手感与美术验收时一致）。

**(b) 尚未解决的缺口——编辑器与运行时的锚点来源不同**：
```
【编辑器】 身体动画 →(完整身体驱动, 锚点带时序动态)→ Pyrrha/Kawaii → 美术所见
【运行时】 θ_t → QNN →(逐帧准静态锚点, 无自生成惯性)→ Pyrrha/Kawaii → 渲染
```
"复用同一套参数"保证的是**物理层行为一致**（同样锚点同样参数，摆幅/阻尼/手感一致），但**不保证整条管线输出一致**——编辑器里美术调参看到的锚点是"身体动作完整驱动"（带速度、带时序），运行时全 QNN 后锚点是"逐帧准静态"（锚点自己不生成惯性/摆动）。同样的弹簧被"会晃的锚点"带 vs 被"静态锚点"带，摆出来的动态是两回事。这个缺口需用 (b) 的一次性并排对比来验证，而非参数标定。

**Blend 兜底（灰度策略，非一次性押注）**：若 (b) 验证下来"本套装动作"的运行时效果美术不接受，可退而求其次——**本套装自己的动作直接播权威动画，只在切到混搭时从权威动画 blend 到 QNN**。设计要点：
- blend 只对**锚点**（$\chi_{target}$）做几帧线性/三次插值，不需要对最终渲染骨骼位置额外 blend（Pyrrha/Kawaii 是有状态阻尼解算器，锚点小跳变会被其阻尼动力学吃掉一部分）；
- blend 窗口长度对齐**身体动作切换本身的融合时长**，不给裙摆设不同步的时长；
- 切换点落差大小由 (a) 精度决定：(a) 好则切换几乎无感，(a) 不够好则兜底方案只能把"明显跳变"降级为"明显不像"；
- **保留 Blend 兜底 = 锁定"混搭部分"的包体收益，但放弃"本套装动作部分"的包体收益**（本套装动作的裙摆动画仍需打包）。建议先按有 Blend 兜底上线保下限，同时独立跑 (b) 验证，验证通过再逐步把本套装动作也切纯 QNN、移除对应动画资产。

**体积与 CPU 的双维度评估（待实测）**：全走 QNN 省的是**包体体积**，换来的可能是**运行时 CPU 开销增加**（本套装动作也从"采样一条压缩曲线≈零成本"变成"每帧跑网络前向 + Pyrrha/Kawaii 物理迭代"），移动端多角色同屏时这笔 CPU 账需单独算。
- 裙摆动画资产粗估：15~20 骨骼 × 每动作 60~150 帧 × 每套 20~50 条动作，ACL 类压缩下单套数百 KB、300+ 套合计百 MB 量级；
- QNN 权重粗估：小 MLP 几十万参数级，fp16/int8 量化后**每套几十~一两百 KB**，且**不随动作条数增长**；
- 方向上 QNN 有数量级优势（且优势随每套动作数增多而扩大），但这是经验粗估，**需拿真实数据跑一次对比**——QNN 权重体积到底多大当前没有概念，需实测确认。

**主动学习验证目标**：流程跑通后应能验证——在 300 套时装 × 动作数据库内新增时装/动作时，只需针对性补少量特定帧的适配动画（补帧边际成本 ≈ 数帧到数十帧级），而非全量录 clip。方法3 的姿势清单应从"静态边界姿势"改为"**其它时装动作库在训练数据覆盖上的稀疏缺口**"来驱动。

## 核心难题：训练标签如何从"动态"转成"静态"

美术输出的训练动画（当前纯手K，后续可能 Houdini/Pyrrha 模拟+精修）**本身带时序和物理**——直接拿来训练准静态 QNN 是错配的：QNN 要学的是"姿态 $\theta$ 被钉住不动时，裙摆骨骼应该在哪"，而 authored 帧记录的是"实际运动轨迹上的瞬时状态"，两者不等价。

### 信号分解

先扣掉刚体驱动，只在**服装参考系**下处理——这是 [[Pan2022-VirtualBones]]、[[HyperBones2026]]、[[PhySkin2026]] 都统一采用的建模前提（身体先做一次 LBS 得到 $\chi^{skin}$，网络只预测修正量），标签提取必须遵守同一约定，否则角色在场景里走位/转身会把时间维度的处理搞乱：

$$\chi(t) = \chi_{rigid}(t) + \Delta\chi_{dyn}(t)$$

其中 $\chi_{rigid}(t)$ 是身体 LBS 带动的刚体部分（闭式已知），$\Delta\chi_{dyn}(t)$ 是服装参考系下的相对形变——即我们要处理的对象。再进一步拆解：

$$\Delta\chi_{dyn}(t) = \Delta\chi_{static}(\theta(t)) + \Delta\chi_{transient}(t)$$

$\Delta\chi_{static}(\theta)$ 是姿态 $\theta$ 下的平衡形变（**QNN 的回归目标**），$\Delta\chi_{transient}(t)$ 是惯性/历史运动引起的超调、摆动、滞后（要去掉的部分）。

### 方法 0（零成本，先做这个）：挖"已静止"片段直接当标签

对身体关节速度/加速度取范数，找到**持续若干帧低于阈值**的窗口——idle、待机、动作末尾的 hold、clip 之间的停顿。这些帧的裙摆姿态本身就是该 pose 下的真实平衡态，直接用，不需要推断。

- 优点：零推断误差、完全忠于美术已经调好的风格；
- 局限：连续动作（走/跑）clip 里可能没有真正"停"的瞬间，覆盖的 pose 范围有限。

### 方法 1：残差参考系下零相位平滑，得到初始猜测

对 $\Delta\chi_{dyn}(t)$ 做**双向（zero-phase）低通**——`filtfilt` 版 Butterworth，或 Savitzky-Golay / LOESS 局部加权回归。截止频率应低于"惯性摆动"频率、又要跟得上"姿态本身快速变化"的合理形变速度；这两个频段会重叠（快速攻击动作里姿态变化本身就很快），纯滤波在这类段落有歧义，只能当**初始猜测**，不能当最终标签。

**进阶版**：既然已知下游 Kawaii 本身就是一个阻尼弹簧模型（锚点驱动的二阶阻尼振子），可以把这套先验直接用作观测模型，做一次状态空间平滑（类似 RTS smoother）：把 $\Delta\chi_{static}(t)$ 当作缓变驱动输入，联合优化"驱动曲线 + 弹簧刚度/阻尼参数"去解释观测到的 $\Delta\chi_{dyn}(t)$（加时间平滑正则）。比通用低通滤波器更物理。

### 方法 2（推荐主力）：物理松弛精修——warm start 自 authored 帧，冻结 $\theta$

复用 [[PhySkin2026]] 的物理能量（St. Venant-Kirchhoff 拉伸 $E_{StVK}$ + dihedral 弯曲 $E_{dihedral}$ + 碰撞 $E_{collision}$ + 重力 $E_{grav}$）：

1. 每帧（或抽样代表帧）把 $\theta$ 冻结在该帧数值；
2. 初值用**方法 1 的平滑结果，或直接用原始 authored 帧本身**（不从零冷启动）；
3. 跑几十步 Newton/L-BFGS 或 projective dynamics 迭代，让裙摆在固定姿态下沉降到真正力平衡点（零速度、零惯性）；
4. warm start 已很接近答案，计算量可控，也不容易掉进错误局部极小值或自穿模构型。

**关键价值**：这一步是清洗数据的机会——把"不自穿、不外扩超过阈值、贴身"直接实现成能量项或投影（projection）步骤的一部分，在**生成标签阶段**就把美术硬性要求焊进去。

### 方法 3：美术手K静态锚点，作为最高优先级监督

主动设计一份姿势清单：覆盖关节限位边界（大字站、劈叉、深蹲）+ 游戏内常见极值姿态（战斗攻击帧、坐、跳跃最高点），每个姿势美术摆一个静态 drape（物理算 quasi-static，或手感调）。这类样本零噪声，每套时装几十到一百个足够，性价比远高于多录 clip。作主监督/正则，方法 0/2 的样本做补充铺开 pose 覆盖度。

## 数据效率：Pose 覆盖 > 帧数

QNN 逐帧无状态回归，相邻帧身体 pose 高度相关（走一步 90% 时间姿态渐变），4000 帧里大量样本近似重复，有效信息量远小于 4000。

- 对训练姿态按 $\theta$-distance 聚类去重，统计 pose space 有效覆盖密度；
- 稀疏/缺失区域（关节接近极限、clip 未覆盖的战斗/坐蹲姿态）优先靠**方法 3 补锚点**或**纯物理自监督**（直接均匀采样 $\theta$，像 [[PhySkin2026|PhySkin]] 一样对采样姿态做能量最小化，零额外数据成本）填补——这比"多要美术录 clip"杠杆更高。
- 这与 [[Jin2024-RopeChainQNN|Jin 2024]] 只用 5000 帧就够（因为 QNN 不需要时序覆盖、只需 pose 覆盖）是同一个道理。

## 纯自监督（PhySkin 路线）的风险与取舍

[[PhySkin2026]] 的物理能量（拉伸+弯曲+碰撞+重力）收敛出的是"真实物理意义下最省能量的 drape"——**不保证符合美术"贴身、不膨胀、不露底"的风格化要求**。真实物理下宽松裙子在很多姿态（大跨步、蹲）会自然往外摆/往下坠，可能刚好撞上要避免的"露底"。

- 若走纯自监督，必须在 loss 里额外加"贴身/安全域"约束（裙摆节点距对应 canonical LBS 位置超过阈值就罚，下摆区域加更强的"跟随身体"先验刚度）——把美术意图显式编码进约束，别指望纯物理 energy 自然产生这种克制感；
- **更安全的做法是方法 2**：把物理松弛的初值锚定在 authored 帧，隐含"以美术数据为准、物理只负责去噪去动态"的保守策略，比完全重新自监督更贴合"美术已经调好风格，只要去掉时序动态"这个诉求。物理自监督更适合当**兜底**（填补 pose 覆盖空白），不适合当主监督信号。

## 下游耦合：QNN 输出连续性正则

因为下游要接 Kawaii（对锚点运动敏感），训练时建议加一个轻量 Lipschitz/平滑正则：对采样的 $\theta$ 加小扰动 $\epsilon$，惩罚 $\lVert f(\theta)-f(\theta+\epsilon)\rVert$ 过大。防止网络在 pose 空间里输出跳变，避免"平滑姿态输入 → 抽搐裙摆输出 → Kawaii 被喂错误速度 → 表现诡异"的连锁反应。

## 落地顺序（当前计划）

1. 方法 0（挖静止片段）——零成本先跑通整条 QNN pipeline，验证架构；
2. 方法 1（残差参考系 + 零相位平滑）——补上非静止帧的 baseline 标签；
3. 方法 2（物理松弛精修，warm start 自 authored/方法1结果）——把美术硬约束焊进标签生成，产出最终高质量数据；
4. 与美术流程结合：设计主动姿势清单，请美术单独摆静态 drape 补关键锚点（方法 3）；
5. Pose-space 去重与覆盖度分析，指导"该为哪些姿态追加数据"而不是无差别多录 clip；
6. 训练阶段加输出连续性正则，为下游 Pyrrha/Kawaii 接力做准备。

## 统一锚点方案：AnchorDEF 移植可行性（2026-10-09）

> [!abstract] 定位
> 研读 [[AnchorDEF-2023-中文翻译|AnchorDEF 2023 中文译本]] 后的方案扩展，回答下方「待展开」第一条——**每套时装是否共享一个 QNN**。结论：**可做，但不能原样搬**，需三处关键改造。本节是设计稿，两个离线验证实验（见文末）落地前不进入正式路线。

### 与 AnchorDEF 原方案的三处错配

| # | AnchorDEF 原设计 | 本项目约束 | 错配 |
|---|---|---|---|
| 1 | 锚点定义在**每件服装自己的网格模板**上（k-means 初始化 + QEM 自适应更新都是 per-garment），VTO 只有 dress/T-shirt 两件、各自训练 | 300+ 套时装，要**一套统一锚点** | 原论文从未演示跨服装统一；其第三贡献（自适应锚点更新）本质就是 per-garment——QEM 把锚点推向**这件**裙子的褶皱 |
| 2 | 输出是**网格顶点**（锚点 LBS + canonical 位移 $D$，顶点级） | 硬约束：美术已定好 LBS 绑定，运行时必须出**美术骨骼 pose** | 顶点级输出无法直接进骨骼驱动管线 |
| 3 | GRU 学时序动态回归 | 已排除 GRU（4000 帧预算下数据饥渴被放大） | 生成层整个换掉，换成 QNN 准静态层 |

另有一处**数据形态差异反而是优势**：AnchorDEF 只有顶点级监督、没有每帧真值变换，所以才要靠 $\mathcal{L}_{consis}$ 等 loss 端到端"逼"出锚点变换的物理含义；而本项目每帧都有静态标签（美术骨骼静态 pose → LBS → 变形网格），锚点变换可以直接**闭式算出来当监督标签**——比 AnchorDEF 的联合学习更稳更便宜。

### 核心改造：锚点从"服装表面"搬到 canonical 裙装空间

动机与 [[HyperBones2026]]（FPS 虚拟骨）、[[PhySkin2026]]（FPS 服装节点）同源：**控制点定义在与具体服装拓扑无关的域上，服装特异性转移到权重和条件码上**。

**统一锚点集 = 身体参考系下的"环 × 高"网格**：

- 以根关节 $J_{root}$（髋）为原点、双腿轴线为参照，定义经纬柱面坐标 $(\varphi, h)$——如 16 列 × 8 行 = 128 个锚点位（对齐 AnchorDEF 160 最优、PhySkin 128 最优的数量级）；
- 裙摆骨骼本来就是"腰部一圈竖直链"结构，环×高网格与美术 rig **天然同构**，锚点→骨骼映射因此顺理；
- **裙长差异用归一化高度处理**：$h \in [0,1]$ 从腰到该裙下摆；短裙只激活上半部分锚点，超过下摆的锚点对该时装 deactivate（权重置零）；
- **宽松/紧身策略统一**：本项目域全是裙摆=宽松类，全部用 AnchorDEF 式 (3)（相对 $J_{root}$ 的根关节参数化），原论文的混合分类问题在这里天然消失。

**自适应更新的"语料级翻译"**：原论文 QEM 把锚点推向单件裙子的褶皱；统一方案改为——对 300 套裙子各自跑 QEM 简化，把"关键区域密度"投影到 canonical 网格上**取平均**，得到全语料共性密度图（预期集中在下摆、双腿间、侧缝），按此加密锚点。**共性褶皱结构进锚点布局，每套裙子的个性褶皱交给下游 Pyrrha/Kawaii 和美术 rig 扛**——与"QNN 只做低频准静态层"的既有分工一致。

**每套时装的特异性转移去向**（统一后的必然分工）：

| 个性来源 | 机制 | 出处 |
|---|---|---|
| 混合权重 $w_{mn}$ | 每套时装在 canonical 空间按距离初始化（每顶点绑最近 8 个锚点），可像 PhySkin 一样**进训练** | PhySkin 表 3 证明可训练权重收益 |
| 时装条件码 $z$ | FiLM 调制共享网络（$\gamma_\ell(z) \odot h^\ell + \beta_\ell(z)$），每套离线算一次、运行时零增量 | HyperBones |
| 精细风格 | 不进锚点层——美术 rig + 下游物理 | 本项目既有架构 |

### 五阶段流程

**Phase 0：canonical 裙装空间 + 300 套注册**（最大工程风险所在）

1. 定义 canonical 环×高网格（锚点布局按 QEM 聚合密度加密）；
2. 每套时装：分割裙摆区域（腰线以下顶点）→ 每顶点算 canonical 坐标 $(\varphi, h)$ → 离线算锚点-顶点混合权重（softmax 距离、top-8 稀疏）→ 超下摆锚点 deactivate。
3. 纯几何、无训练，是每套新时装边际成本之一（分钟级离线计算）。

**Phase 1：锚点变换标签生成**（闭式，复用既有静态标签管线）

```
θ_t ──(方法0/1/2/3)──> 美术骨骼静态pose ──(美术LBS)──> 静态变形网格 V_gt(θ_t)
                                                        │
对每个激活锚点 p_n：取其 K 近邻顶点（canonical 集合与变形后
对应集合），Kabsch/Procrustes 闭式解 ────────────> 锚点变换标签 (R_n, T_n)
```

**这是对 AnchorDEF 最重要的简化**：原论文靠网络 + $\mathcal{L}_{consis}$ 联合学习锚点变换（因为只有顶点监督）；本项目有每帧网格真值，局部 Procrustes 直接给出带物理含义的标签——Kabsch 解天然满足"锚点变换 = 邻域平均变换"（式 10 的一致性是**构造性质**而非训练目标）。逐帧独立、闭式、无 SSDR 那种全局分解的不稳定性。$\mathcal{L}_{dir}$ 类防穿透思想仍可作训练期正则保留。

**Phase 2：共享 QNN 训练**

- **架构**：无状态逐帧 MLP（对齐 QNN 路线，无 GRU），输入身体 pose $\theta$（可加平移/速度特征），FiLM 层接收时装码 $z$（从 canonical 网格特征编码：裙长、摆角、层数、版型描述子，或 learned embedding）；输出全部激活锚点的变换（旋转用 6D 表示或四元数，**不学原论文的欧拉角**）；
- **参数化**：全部用宽松型式 (3)，相对 $J_{root}$——大范围跟随由根关节变换闭式承担，网络只学裙装参考系内的相对变换（与 Pan/PhySkin 一脉的"闭式扣掉刚体、网络只学修正"原则）；
- **损失**：锚点变换 vs Phase 1 标签（主监督）+ 网格级 $\mathcal{L}_{rec}/\mathcal{L}_{lap}$（经每套 $w$ 的锚点 LBS 折到顶点，保证权重质量）+ 防穿透正则 + **输出 Lipschitz 平滑正则**（下游 Pyrrha/Kawaii 接力的既有计划，防锚点跳变喂坏弹簧）；
- **数据**：300 套 × ~4000 帧 ≈ 120 万帧，对共享模型绰绰有余；无教师蒸馏，训练成本远低于 HyperBones 的 99.5k epoch。

**Phase 3：锚点 → 美术骨骼接口**（统一方案真正的成败点，即"每套时装骨骼结构不统一"矛盾的具体化）

- **路 A（推荐先验证）：离线拟合每套一个轻量映射**。裙骨是竖直链、锚点是环×高网格，每根美术骨骼天然对应 1–2 个邻近锚点；在训练帧上做一次最小二乘：美术骨骼变换 ≈ 邻近锚点变换的加权组合（系数 per-garment 一次拟合，运行时零学习成本）。验收指标直接可量化：映射重建误差分布。
- **路 B：跳过映射**。既然下游本来就是"QNN 出锚点位置 → Pyrrha/Kawaii 弹簧"，可让**统一锚点直接充当运行时统一虚拟裙骨**（喂给物理层的锚点就是它们），美术骨骼只在最终 LBS 渲染时用——per-frame 解小规模骨骼最小二乘，或美术 rig 保留"被锚点驱动"的 IK 式映射。改动运行时架构更多，但"统一"做得最彻底。

**Phase 4：验收（对齐既有 a/b 双线）+ 消融**

- **(a) 锚点层**：预测变换 vs Phase 1 闭式标签的误差分位数 + 锚点 LBS 后网格误差——纯回归，可直接打分；
- **(b) 整链**：QNN → 锚点 →（映射）→ 美术骨骼 → Pyrrha/Kawaii vs 美术权威动画并排对比——照既有 (b) 方案，一次性评编辑器/运行时锚点来源差异；
- **消融**：共享模型 vs 每套单独训；锚点数（64/128/160，注意原论文 320 反而崩的教训——统一大锚点集上此风险更要防）；**新时装 zero-shot（只算 $z$ 和权重）vs 4000 帧微调**——微调一条应作为"每套边际成本"的主答案。

### 风险清单

| 风险 | 等级 | 缓解 |
|---|---|---|
| canonical 注册质量：裙长/层数/A字 vs 铅笔裙/百褶差异大 | **高**（最大工程风险） | 先拿 20–30 套形态差异最大的裙子试跑 Phase 0；百褶/多层可能需 per-garment 权重承担更多 |
| 锚点→美术骨骼映射精度（路 A） | **高**（架构成败点） | 先离线验证：拿已有动画数据直接拟合并统计重建误差，不用训任何网络即可出结论 |
| 共享模型风格平均化（美术调好的个性被抹平） | 中 | FiLM 条件码 + 每套微调；(a) 验收线直接量化 |
| 统一锚点数不够表达最复杂长裙 | 中 | 高度归一化 + 分段激活；必要时按裙长分桶训两个规模 |
| 收益 | — | 新时装边际成本从"全量训练"降到"离线注册 + 算 $z$ +（可选）4000 帧微调"；混搭动作跨时装泛化是共享模型的免费收益 |

### 判断与下一步

拆开看，真正从 AnchorDEF 搬过来的只有三件东西：(a) "表面附近刚体变换混合 + 残差位移"的表示分解本身（与 [[VirtualBones]] 同构，非它独有）；(b) 位置/法向/方向一致性约束的思想（因有真值标签而退化为闭式构造 + 正则）；(c) QEM 密度指导锚点布局（语料级聚合）。其余全部来自本谱系：准静态思想来自 [[Jin2024-RopeChainQNN]]/[[QNN]]，条件化来自 [[HyperBones2026]]/[[PhySkin2026]]，标签管线和下游物理是既有设计。AnchorDEF 的价值是**确认"锚点/虚拟骨骼+LBS+残差"表示在宽松裙装上是最优档位**（其表 3 对 TailorNet/VirtualBones 的全面优势），而非可直接套用的管线。

> [!todo] 先做的两个离线实验（顺序有讲究，前两步都不用训网络）
> 1. 拿 5–10 套已有动画数据的裙子离线跑 Phase 1 的 Kabsch 标签 + 路 A 映射拟合，验证"锚点→美术骨骼"接口的误差上界；
> 2. 拿 20–30 套形态各异的裙子跑 Phase 0 注册，看 canonical 空间覆盖率。
> 这两个数字出来，"可做吗"就能从判断变成结论。

## 待展开（后续迭代方向）

- 每套时装是否共享一个 QNN，还是每套单独训练？→ **2026-10-09 已给出候选答案**：见上方「统一锚点方案」一节——canonical 环×高锚点 + FiLM 条件码回答服装拓扑无关，锚点→美术骨骼离线映射回答骨骼结构不统一；待两个离线实验验证后升级为正式路线。原参考 [[PhySkin2026]] 的点采样 Transformer 编码思路仍作为备选编码方案。
- 如何把"紧贴度"量化成一个可调参数交给美术调节，而不是写死在 loss 权重里。
- 方法 2 的物理松弛在自穿模严重的初始构型下是否稳定，需不需要专门的碰撞检测预处理再进入能量最小化。
- 若未来数据量/算力条件变化，是否值得重新评估 [[HyperBones2026]] 的教师蒸馏路线（比如某些时装确实需要更强动态表现、Kawaii 不够用的场景）。
- **下游物理层候选是否从 Kawaii 扩到 [[PyrrhaPhysics]]？** 运行时下游物理拟用 Pyrrha(裙摆/头发)+Kawaii(身体抖动) 接力，参数由美术在编辑器调好、运行时复用；但 Kawaii 模拟裙摆存在结构性缺陷（子骨骼碰撞不传导、易穿腿、链条长后发弹），Pyrrha 的杆模拟更物理、带动态碰撞器与层 ID 防自穿。需要验证 Pyrrha 作裙摆下游后，Kawaii 是否仅保留"身体抖动"职责（该分工下两者不冲突）。
