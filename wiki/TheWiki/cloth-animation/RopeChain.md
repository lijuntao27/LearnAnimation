# Rope Chain（绳链）

> [[Jin2024-RopeChainQNN|Jin 2024]] 提出的低 DOF 布料物理模拟结构，§3-6。它是整条流水线的**动态发动机**：裙摆怎么摆、怎么甩，全由它产生。

## 定义与布局

把 [[VirtualBones|虚拟骨骼]] 纵向串成绳链，每根绳 inextensible yet shrinkable（不可拉伸但可缩短）。**只模拟骨骼的平动位置（translational DOF，无旋转）**。

```
身体(骨盆/腰) ──► 链根 θ₀：运动学约束，直接跟随身体
                    │
                   θ₁  其余骨骼在 重力/惯性/风/碰撞 下自由演化
                   ⋮
                    θ₈  （裙摆下摆）
```

- 规模：披风 12690 顶点 → 10 chains × 13-15 bones（DOF ↓~90×）；裙摆 18546 顶点 → 26 chains × 9 bones = 234 骨骼（DOF ↓~80×）
- 身体动画通过**链根 θ₀ 被钉在身上**耦合进来：身体一走，θ₀ 被拖、下方整条链靠惯性甩起 = 裙摆跟身而动、随后回摆的来源

## 为什么不用质量弹簧

| | 质量弹簧 | rope chain |
|---|---|---|
| 拉伸 | 弹簧抵抗，过强 locking、过弱 overstretch | 不可拉伸（trivial）|
| 弯曲 | 线性化旋转抵抗 | 自由 buckling |
| 旋转/摆动 | 过抵抗，摆不开 | 自由摆动 |
| 验证 | Fig 3 锁死/拉过头 | Fig 4 两骨摆与解析单摆解几乎重合 |

**松了不罚**是灵魂：绳到最大长度才约束，否则自由——所以能大摆幅、不 rubbery。可选**横向弱软弹簧**连接相邻绳链，防整圈各自乱飞（软约束，引导不强制）。

## 时间积分：半隐式 Newmark（中央差分）

每时间步四步：

```
① 半步速度更新：外力（重力、风阻、相对父骨骼阻尼、横向软弹簧）
② 位置更新：显式中点推进（central differencing）
③ 碰撞解析：非运动学骨骼 vs 身体解析 SDF
④ 再补半步速度
```

**为什么中央差分而非 fully-implicit（backward Euler）**：后者的数值阻尼会把高频弹道运动"炖糊"（回摆软绵绵）；中央差分对高频动态保真得多（论文原话，Fig 5 佐证）。

## 约束求解：一次 sweep 够

绳到最大长度 → 两骨骼互相绕转（球面约束的摆）：

- **张力**（速度约束）：解三对角不等式组，Gauss-Seidel **tip→root** 扫一遍 → 即使扫一次，每根骨骼也知道下方所有骨骼的重量
- **冲量**（碰撞后速度交换）：**root→tip**（接触解析的惯例）
- **位置更新**（最严格）：root→tip 强制绳长：**松 → 自由跑；紧 → 限制在球面上转**

实时场景通常各 1 次 sweep（Fig 5：迭代越多越不阻尼）。

## 碰撞：只在骨头上、解析 SDF

- 只对 234 根**非运动学**骨骼 vs 身体做碰撞（不做整网格）
- SDF = **解析闭式体素**（球/胶囊等，Fig 6），非 3D 网格 SDF（内存贵）
- **history-based push out**：沿"穿入前反向路径方向"而非梯度推出（薄物体/高曲率时梯度方向不可靠，Fig 7 绿粒子最稳），并投影速度；碰撞可迭代数次，实时取 1 次

## 输出与代价

输出每帧 234 根骨骼的**平动位置**（无旋转）。代价：

- 无旋转信息 → LBS / DQS 全失败 → 必须 [[PCA|neural skinning]] 学"骨骼→网格"
- 只捕获粗结构动态；高频表面细节由 [[QNN]] 事后补
- 无法保证 OOD 输入下网格完全不穿透（PINN 碰撞 loss 缓解）

## 在方案里的定位

```
rope chain 物理 = 动态发动机（甩、摆、碰撞弹开）──> 234 骨骼平动位置
        │                                          │ x_t（去刚体）
        ▼                                          ▼
 取代 GRU 学时序（Pan 需 40000×10 帧且泛化差）  neural skinning + QNN 画网格
```

**动态归物理、形状归网络。** 物理擅长弹道、网络擅长高 DOF 形状——rope chain 是省数据的总开关（5000 帧够训的前提）。
