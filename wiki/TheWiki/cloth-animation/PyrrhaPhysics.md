# Pyrrha Physics — 网易内部 TA 自研骨骼级物理方案

> 公司内部艺设三部 TA 组自研的角色物理方案（运行时轻量物理求解器，非数据驱动/神经网络）。原文全文与联系方式见 [[RawSource/articles/PyrrhaPhysics-KM|PyrrhaPhysics-KM]]。本页是其在 SkirtQNN 项目语境下的提炼与判断。

## 一句话

一套在 UE 动画蓝图中运行的**骨骼颗粒度轻量物理**（XPBD 解算，可混合粒子/弹簧/杆/刚体/铰链），自带动态碰撞器、层 ID 防穿插、碰撞器随骨骼缩放等防穿/塑形能力，作者明确将其定位为**裙摆与复杂服饰场景优于 Kawaii** 的方案；正在被 [[SkirtQNN-Design|本项目]]评估为运行时二级物理的候选下游（裙摆/头发用 Pyrrha、身体抖动用 Kawaii 的分工）。

## 与 UE 现有方案的核心对比

| 维度 | UE RigidBody | Kawaii Physics | Pyrrha Physics |
|---|---|---|---|
| 解算器 | XPBD | 线性弹簧(XPBD)+位置恢复(类PBD) | XPBD |
| 元素 | 刚体、铰链 | 粒子、弹簧 | 粒子、弹簧、杆、刚体、铰链 |
| 模拟骨骼碰撞器 | Sphere/Capsule/Box/ConvexHull | **仅 Sphere** | Sphere/Capsule/Box/ConvexHull/**Triangle** |
| 适用场景 | 刚体铰链饰品 | **飘带、单根骨骼抖动** | 饰品、飘带、**裙摆、复杂服饰** |
| 穿透后修复 | 无 | 无 | **调整碰撞排斥方向，引导修复** |
| 真实感 | 较物理 | **不物理** | 较物理 |
| 高速变换应对 | 角/线速度上限 | 自动传送 | 自动传送 + 角/线速度上限 |

## 关键特性

- **混合模拟**：粒子/弹簧/杆/刚体/铰链同一资产内混合（例：裙摆布料 + 头发生 + 链子刚体）。刚体挂坠震荡细节质点模拟不出；杆模型比刚体铰链更适合细绳/鞭子；刚体铰链不适合裙摆。
- **动态碰撞器**：约束碰撞器（胶囊，轴长/位置随约束关联骨骼动态确定）+ 三角形碰撞器（顶点由骨骼位置决定）——防"腿从裙摆骨骼缝隙穿出"、防裙摆骨骼稀疏处饰品穿入。比固定在骨骼子空间下的碰撞器更有效。
- **碰撞优化**：基于"修正碰撞排斥方向"方法（与 Messiah 软骨类似但不完全相同），防穿透 + 引导穿透后恢复（开连续性碰撞检测反而可能穿透后无法恢复，故不用）。
- **层 ID**：一件衣服分多层，越靠外层编号越大，可配层间碰撞关系（是否与外层碰撞器碰撞、内层是否被外层撞开等）——**解决多层衣服互穿**。
- **碰撞器随骨骼缩放**：自定义体型游戏需要。球/胶囊/盒/凸多面体均可，用缩放轴投影将缩放分摊到碰撞元素参数。
- **兼容卡通效果**：可切换杆方法为类 Magica Cloth2 的角度恢复（刚性<2），晃动幅度明显易调出卡通灵动感；有旋转位移控制参数可抑制角色整体/动画运动的影响。
- **塑形优势**：骨骼密度低，可用较复杂约束塑形，适合**被龙骨支撑或需要塑形的裙子**（NvCloth/ChaosCloth 细腻但塑性困难、硬裙/龙骨裙不适用）。可混合 Pyrrha + Chaos Cloth（上半软骨塑形 + 下半布料细腻）。软骨性能优于布料，适合移动端。

## 与 SkirtQNN 项目的关联（判断）

1. **Kawaii 的结构性缺陷**：Kawaii 子骨骼碰撞**不能传导给父骨骼**（从下往上撞时无法有效防穿插）、模拟裙摆**容易穿腿**、链条节数变多后发弹且硬度受迭代次数/帧率影响。这**直接挑战了 SkirtQNN-Design 中"下游物理层由 Kawaii 兜底二级动态"的架构假设**——若下游真的要用 Kawaii 扛裙摆，这些缺陷会顶到美术"不能穿模、不能自穿"的硬约束上。
2. **可能的职责分工**：文章暗示 Kawaii 适合"脂肪抖动和飘带"，Pyrrha 适合"裙摆/复杂服饰"——即**Pyrrha 管裙摆/头发，Kawaii 管身体抖动** 的候选架构（本项目正在评估的运行时分工）。
3. **美术硬约束的工程参考**：Pyrrha 的"层 ID 防穿插"+"动态碰撞器"机制，是 [[SkirtQNN-Design]]"不能穿模、不能自穿"硬约束的下游实现参考；QNN 若作为其上的一层锚点网络，可因此把贴身/防穿要求更多交给物理层，自身输出不必过度保守。
4. **技术路径关系**：Pyrrha 是**运行时纯物理**（零训练数据、零网络），与 QNN+下游物理路线是**不同取舍轴**——QNN 的存在价值不在"省掉物理"，而在"运行时物理不可控处提供一个美术风格的锚点近似 + 降性能开销/降每套时装调参负担"；两者是互补（Pyrrha 作 QNN 下游）或部分替代（Pyrrha 直接扛动态）关系，需在 [[SkirtQNN-Design]] 待展开中留开放问题。
